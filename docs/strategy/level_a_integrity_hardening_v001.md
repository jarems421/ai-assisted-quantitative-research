# Anvil / Crucible: prospective Level A integrity preflight V001

**2026-10-24 · Offline implementation; no real approval, acquisition or study.** This is the separately reviewable follow-up to [the readiness audit](anvil_crucible_readiness_audit.md), stacked on PR #30. It adds [a small read-only preflight](../../src/research/study_readiness_v1/gate.py) for one frozen design. It does not change [Measurement Gate M](measurement_gate_m.md), Level A/B/C, historical Discovery classifications or research authority. A V001 Discovery `LEVEL_A_DESIGN_CANDIDATE` disposition alone is insufficient to satisfy this new preflight.

The executable protections refuse invalid **new-profile readiness**, rather than rewriting old scientific records. There is no study runner or new Store transition. `inspect` always returns `ready: false`. `verify` can return `OWNER_REVIEWED_LEVEL_A_PREFLIGHT` only after mechanical checks and a separate exact-scope signed review; all outputs retain `authorises: []`. The signature records the owner's approval of the bounded local-analysis design. It grants no acquisition, model, market-data, Level B/C or trading authority, and dispatches nothing. Actual investigation still needs the applicable committed campaign authority and existing source-stop checks.

## What the code checks

`LEVEL_A_READINESS_V001` is an additive manifest, outside `discovery/`, `graph/` and Scout's frozen import closures. [The synthetic fixture builder](../../tests/test_study_readiness.py) is the executable complete example, using an actual Scout FORGE handoff and an actual replayed Discovery ledger. All source text, keys and review stand-ins in tests are explicitly fictional.

The packet's directory contains the manifest and its referenced local artifacts. References are relative paths with SHA-256; paths leaving that directory are refused. Keep real packets and unpublished originals in private, ignored storage. Never commit originals, signing keys, raw model answers or account information.

The manifest has these exact responsibilities:

| Object | Required content |
| --- | --- |
| `schema`, `fixture`, `level`, `claim` | Profile V001; fixture agrees with the ledger and Forge card; level A and `RETROSPECTIVE_ECONOMIC_ONLY`. |
| `ledger`, `ledger_head`, `candidate`, `m_review_id` | Exact ledger bytes/head; latest frozen candidate ID/version/digest; latest exact-version evidenced M review. Current mechanical M blockers, a later HOLD/REJECT or a superseded M review refuse readiness. Both historical M-pass and current design-candidate dispositions must exist. |
| `origin` | Exact handoff file/hash and card ID/version/hash; original and mapped predictor/outcome quantity/units/falsifier and complete mechanism, plus explicit reasons for changes. A proposed hypothesis may be reformulated explicitly; it cannot silently become the same originating claim. |
| `evidence[]` | Stable local ID, original locator, exact version, optional archive reference, file/hash, ORIGINAL/complete flags, format, passage and table/page/field location. Retained original bytes and their hash suffice without a separate external archive. UTF-8 passages are found in retained bytes; binary originals use `BINARY_HUMAN_LOCATION` and need human inspection. Completeness and authenticity flags are assertions for the human to verify. |
| `measurements[]` | Exact observation ID/version and Source Passport ID/version; evidence ID and field/passage location; value, units, denominator, entity, asset/cohort/geography/accounting scope, economic period and MEASURED/REPORTED/ESTIMATED/FORECAST/CONDITIONAL nature. Values, units, denominator, entity and original hash must match the ledger. JSON pointers reproduce numeric readings; `HUMAN_PASSAGE` records an unautomated reading. |
| `measurements[].public_time` | Either `RETROSPECTIVE_ONLY`, or `EXACT_VERSION_CERTIFIED` with content hash, certificate evidence ID and publication time. The latter's metadata is not an automatic Level B certificate. Never inherit an old page's publication date for later revised measurements. |
| `construction[]`, roots | Explicit numeric dependency nodes. V001 supports IDENTITY, SUM, DIFFERENCE and a small dimensional CONVERT table; no arbitrary code, plug-in, formula interpreter or hidden tool execution. Output values are reproduced; arithmetic cannot mix declared denominators/scopes. Predictor/outcome leaves and original hash/location pairs must be disjoint, and all mapped measurements must be used. |
| `financial_crosswalk` | Gross or net basis, exact candidate amount/units, denominator and meaning, source evidence/location/extraction and economic scope. Nonmonetary or more complex bridges need a separate reviewed profile, rather than passing a guessed conversion. |
| `join` | Ordered actual relationship IDs, traversal direction, original evidence, full historical date coverage and consistent economic scope. Each edge must connect the current node; the path must terminate at the exposure company and include the outcome entity. An explicitly reviewed `ENTITY_WIDE_OWNERSHIP` edge between legal entities may have NOT_APPLICABLE asset/geography in its original record; this permits an ordinary subsidiary-parent hop without inventing an asset-specific ownership document. UNKNOWN or contradictory scope never qualifies. Allocations need DOCUMENTED original evidence and the existing verified quantity-transfer record. Names/tickers alone are refused. |
| `selection_history` | Re-derived from *every* version of the candidate and declared related claims, and their used source/observation/relationship revisions. Selected, unknown, reformulated or synthetic histories cannot claim prospective untouched evaluation. Nothing relabels stored V001 derived fields. |
| `design` | Question, falsifier, eligible population and observation unit; root mappings; baseline and competing explanations; temporal order and reconstruction limits; missingness, duplicates, dependence, uncertainty, inference, analysis family and stopping rule; EXPLORATORY/CONFIRMATORY status and evaluation label. `uncertainty_plan` states method, estimand, independent unit, dependence handling, adequacy check, multiplicity, limitations and `DESCRIPTIVE_ONLY_OR_STOP` if assumptions fail. Historical actionability and causal claims are refused by this narrow profile. |
| `owner_scope` | `LOCAL_LEVEL_A_ANALYSIS`, exact evidence IDs, explicit limits; zero network requests, model calls and spending. The signature binds this exact scope and the design digest. Expanding scope requires a new packet and review, never a reused approval. |

The conversion table is an implementation, not free-form metadata: e.g. tonnes/day → kg/day is exactly ×1,000; ×100 is refused. It does not infer period durations, currency exchange, spare capacity, gross-to-net economics or a denominator from prose. Unsupported transformations stop preflight and need a reviewed, versioned extension. Estimated/forecast/conditional predictors are visibly labelled; a forecast or formula is never accepted as a realised outcome.

## Independent review and owner control

[Verification](../../src/research/study_readiness_v1/approval.py) uses OpenSSH detached signatures with namespace `research-os-level-a-v001`. This is a per-study review control, not a signed-release policy or identity platform. No real trust file, key enrolment, human judgment, signature, M decision or study authorisation was created in this task. The package contains **no signing command**.

The owner, independently of the assistant, must enrol `~/.research-os/level-a-trust.json` with schema `LEVEL_A_OWNER_TRUST_V001`, `fixture: LIVE`, a chosen `principal`, absolute `allowed_signers` path and that file's `allowed_signers_sha256`. Both trust and signer files must be outside the checkout and packet. The allowed-signers file contains the owner's chosen public key and principal in OpenSSH format. The CLI has no packet-controlled trust option. Synthetic trust cannot verify a LIVE packet.

**Trust boundary:** the owner must independently check and protect these trust files, and keep private signing capability unavailable to the assistant, for example on a separate owner-controlled device. An assistant or attacker with authority to replace local trust or access the signing key can defeat this control. The signature establishes possession of the enrolled key and exact bytes, not biological identity, independence, intent, original-source authenticity or correctness. If that separation cannot be arranged, readiness stays blocked; a `HUMAN` label or an interactive terminal is not a substitute. No existing personal/account SSH keys are read by the tool or tests.

`inspect` emits an unsigned `review_payload` with **PENDING**, empty notes and empty evidence references for all eight reviews. It does not draft favourable human judgments. The human separately inspects the originals and completes source meaning, independence, historical join, selection history, Forge mapping, study design, exact M reaffirmation and owner scope. Each review must reference the packet's evidence IDs and provide its own reason. Add the enrolled `owner_principal`; sign the **canonical JSON bytes** of that completed payload on the owner-controlled device, using the namespace above. JSON canonicalisation is the repository's sorted-key, compact UTF-8 JSON convention (`src.research.spec.canonical`); pretty-printed bytes are different. The signed review is the independently reviewable owner record, retained with the frozen design. Do not ask an assistant to fill VERIFIED judgments or sign for a human.

`verify` replays/checks the packet again, checks the complete scope binding and invokes only `ssh-keygen -Y verify` (no shell, key generation, signing, network or model). Missing tool/trust/signature, an unrelated existing file, altered review, changed design/inputs/code or bad signature fails closed. Signature verification is tested with disposable synthetic keys on the guarded public CI path; pure adversarial tests label their mocked verifier explicitly.

## Concise real-study preflight

1. Owner chooses **one** hypothesis and separately approves a campaign/source scope consistent with existing stops. No request follows this document. Retain the original Scout archive and exact exported Forge handoff privately.
2. Record provisional Discovery evidence without upgrading its meaning. Freeze the exact candidate; complete actual human M/H review and disposition under the unchanged rules. An assistant may prepare a crosswalk but cannot supply the reviewer's judgment.
3. Inspect one original predictor, independently measured realised outcome, actual dated exposure path and financial scale. Fill the crosswalk from those exact versions. Check completeness, denominator, gross/net, observation period, cohort and historical ownership. Independently inspect every required semantic/allocation claim.
4. Write the small design above. A purposive or already-seen positive control is retrospective/exploratory, never untouched confirmation. Fix the estimand, population, baseline, dependence/uncertainty treatment, family and stopping/fallback rule before running any analysis.
5. Place the exact local artifacts in the private packet; freeze their hashes and the complete ledger head. Run:

   ```powershell
   python -m src.research.study_readiness_v1 inspect <private-packet>/packet.json
   ```

   A clean mechanical packet returns `INDEPENDENT_REVIEW_REQUIRED` and exit 2, **not ready**. Any decisive gap stays BLOCKED or PENDING. Recording a provisional hypothesis is still allowed in Discovery.
6. Owner independently reviews and signs the completed review payload with the protected enrolled key. Retain that record and the frozen packet/head outside the mutable research workspace as well. Verify locally:

   ```powershell
   python -m src.research.study_readiness_v1 verify <private-packet>/packet.json <completed-review>.json <completed-review>.json.sig
   ```

7. Compare the returned design/scope digests against the owner's retained copies. Only then consider the separately authorised local Level A analysis. This command neither launches nor certifies it. Recheck preflight immediately before use; any scope, implementation, source or design change needs a new signed review. No price/return inspection, acquisition, paid call or subsequent level follows automatically.

## Regressions, compatibility and residual limits

[Enforcement regressions](../../tests/test_study_readiness.py) reproduce unsupported field mapping, circular/transitive/renamed measurements, incorrect unit conversion, unrelated verified assets/cohorts/accounting scope, historical ownership backfill, old certificates on revised content, outcome-route revision with a preserved V001 `CLARIFICATION`, cleared inspection history, invented HUMAN labels, unrelated authority files, Forge mapping drift, omitted population/baseline/uncertainty and stale M/dispositions. They also admit a correct conversion, same-publisher independent outcome, ordinary retrospective reconstruction, reverse ownership traversal and a legitimate multi-hop path to **review**, never automatic scientific approval. [The native signature regression](../../tests/test_study_readiness_signature.py) accepts exact synthetic signed bytes and refuses altered review text, forged signatures and changed trust files. These are enforcement tests; the old audit's characterization tests remain and still expose the limitations of the legacy path.

The new package is a sibling of Discovery, so it does not enter the existing Discovery/Graph/Scout implementation closures. No shared schema, ledger append/replay rule, derived field, historical fixture, source stop, frozen text or experiment gate is changed. A regression pins and replays all six tracked historical Discovery ledgers: **185 events**, exact SHA-256 and unchanged bytes. The full Graph and Scout suites remain required, including the holdout and pinned-package checks. This branch is stacked on `audit/anvil-crucible-readiness`; PR #30 remains intact and Forge automation is untouched.

Local validation: **49 focused tests** passed, including native synthetic signature verification and historical replay; the guarded public suite (including all Graph/holdout checks) passed, **386 guarded Scout tests** passed, and **212 additional restricted offline tests** passed with zero skips/errors/forbidden operations and 11 explicit existing exclusions. Inventory verification, the applicable Windows guard tests, `graph quality --check`, the six-artifact presentation check and `git diff --check` passed. Linux-specific guard behavior is exercised by Linux CI, rather than treated as Windows evidence. Final-head Windows/Linux CI and its exact commit are recorded in the draft PR checks; a local pass is not a claim that remote CI has completed.

Scientific uncertainty remains substantial. Hashes cannot establish whether a source is authentic, complete or truthfully interpreted. An explicit dependency graph cannot expose a publisher's hidden modelling or an omitted construction step; separate fields can share errors or common shocks. A connected dated path does not establish accounting consolidation, retained economic exposure, obligation, allocation or materiality. Scope strings and stable-looking IDs still need grounded human comparison. A documented uncertainty method can be inapplicable, underpowered or confounded. Undisclosed prior hypotheses and privately viewed outcomes cannot be recovered from the ledger. Local control is not anti-rollback storage, a signature is not identity, and a signed mistake remains a mistake. Passing this preflight establishes no empirical finding, causal effect, actionable signal, alpha or investment edge.

The smallest next steps are owner review of this additive profile, independent trust enrolment/signing separation, and one genuinely inspected source-to-measurement packet plus a bounded frozen design. If those cannot be supplied, the study remains unready. No broad platform work is needed.
