## Reservation and evidence properties

The external registry is distinct from the capture directory. A registry-wide exclusive-create lock protects consumption. An exclusive UUID claim binds the capture path, complete binding hash and approval hash and is fsynced before capture creation or spawn. Capture files are exclusively created. A CONSUMED journal event and its independently exclusive witness are persisted before launch intent; the launch itself occurs only afterwards. Failed spawn and the intent-to-spawn crash interval consume the reservation. Rebinding the same UUID to another capture path fails. Existing captures and stale locks are never reopened, removed or recovered automatically. There is no resume/reset/retry interface.

A STOP also retains the registry lock after sealing its evidence. In particular, an incomplete drain or unknown child exit cannot unlock a later command merely because a receipt was archived. Only a complete local capture releases the lock; its exclusive consumed claim remains permanently in place.

Each journal event has a predecessor hash, sequence, UTC and monotonic receipt timestamps and a separately created/fsynced witness before log append/fsync. Each raw chunk is written, flushed and fsynced **before** its index event. The index records channel, sequence, per-channel byte offset/length/digest and read-observation time. Both pipes drain concurrently through a bounded queue; no decoding, newline splitting, event recognition, de-duplication, tokenization or output assembly happens. Cross-pipe index order is collector receipt order, not provider emission order. Unknown/malformed bytes, invalid UTF-8, partial lines and data following terminal-looking text are preserved.

`audit()` reads originals without changing them, reconciles every indexed byte segment, raw hashes, final receipt, witnesses and independent reservation claim, and detects inconsistent mutations/truncation. A raw-write/index crash retains an unindexed tail and returns `INTERRUPTED_EVIDENCE_RETAINED`; it never fabricates the missing event or promotes the result. A missing receipt, journal suffix rollback or orphan witness cannot pass as sealed evidence. Lock presence remains separately reported. A sealed byte capture says nothing about valid JSON, terminal coverage, model success, generation count or economic quality; a nonzero child exit is retained separately.

This protects against accidental concurrent reuse and inconsistent local edits. **Trusted local filesystem acceptance remains necessary.** An attacker able to delete/clone the claim, lock, journal, witnesses and approval together can defeat local hashes. They are neither signatures nor an external immutable registry. Code/executable hash checks also assume no hostile replacement between check and use. File fsync is requested everywhere; directory fsync is requested on POSIX. Portable Windows directory/power-loss durability remains UNKNOWN. Process-crash tests do not certify storage-device power-loss behavior. Original bytes are immutable through this API; administrator-level filesystem edits are detected when inconsistent, not prevented by OS access control.

## Local process and resource behavior

Native limits remain 600 seconds, 12 MiB combined recorded bytes, read chunks <=64 KiB, five-second cancellation escalation and up to 30 seconds of drain. Shorter limits used in local tests are fixture-specific and bound in simulated permission; native review rejects changed limits. The common candidate output setting remains 32,768. R3's 60,000 planning reference, 120,000 elevated annotation and proposed 200,000 emergency are unchanged. No live native token counter exists here, so numeric live cancellation and final native usage classification remain unavailable pending native observation/profile review. Bytes are never tokens or currency.

The recording threshold retains the crossing chunk (overshoot < one configured read chunk), triggers cancellation and explicitly accounts for any subsequently drained/discarded bytes. Such a capture is a STOP, never a lossless pass. Drain timeout records incomplete EOF/truncation/cleanup. The watchdog requests cancellation; cleanup and persistence can exceed it and are not a hard runtime/work bound. Receipt wall time includes launch and cleanup through receipt construction; the journal timestamps also retain subsequent seal persistence. Blocking OS/storage operations cannot be preempted by this Python watchdog.

The collector records the directly spawned PID, collector PID/parent, OS exit, observed timing, Windows process creation FILETIME when obtainable, per-pipe EOF, stdin completion, drain completion and cancellation call results. POSIX starts a new session; Windows attempts post-spawn job assignment for tree escalation. That assignment has a race and may fail, leaving parent-only control and UNKNOWN descendants. No complete tree-coverage, sandbox, model identity or account-isolation claim follows. Unresolved processes/EOF require operator review and prohibit another command. A terminate/kill call returning successfully is only local OS acknowledgement; remote cancellation always remains UNKNOWN.

All native message/request IDs, terminal semantics, generations, provider requests, usage components, thinking detail, attributable subscription charges and compatibility are UNKNOWN/NOT_TESTED. Local exit 0 and EOF do not substitute for them. Future interpretation must work from copies and define a newly reviewed native profile; original captures remain unchanged and are never tagged as fictional recordings merely because N1 inputs are fictional. Unknown or conflicting final usage cannot become zero or compliant. No regeneration, repair, additional parent invocation or scientific execution is enabled.

## Local validation record

The public suite passed 390 tests; the guarded Scout suite contains 242 tests (four new binding tests); process assurance passed six existing journal tests and 22 new N1 tests. The latter use actual fixed local Python processes, including a dead crash worker and racing reservations. Coverage includes concurrent stderr flooding, byte-split UTF-8, invalid/unknown/missing-terminal content, trailing data, descendant-held EOF, nonzero exit, actual failed spawn, timeout/IO triggers, interruption before spawn and between raw fsync/indexing, index/fsync failure, stale locks, suffix rollback, mutation detection and STOP locking out another reservation.

Initial stress runs exceeded deliberately shortened fixture deadlines under simultaneous disk-intensive regressions. Ordinary fixtures now use a 30-second watchdog and the existing 30-second drain allowance; timeout/incomplete-drain cases still use their explicit short limits. Native 600/30-second limits were never changed. Adversarial review also corrected stopped receipts releasing the registry lock; the direct cross-reservation regression now verifies that STOP retains it. These were local engineering iterations, not scientific attempts or selected model outputs.

All 28 V003 files and the 45-entry original R3 implementation inventory remain unchanged. Of 1,008 baseline files, only the CI workflow changes, solely to add the fixed-subprocess assurance step. This is automated/source-level assurance, not independent human security attestation or hosted acceptance.
