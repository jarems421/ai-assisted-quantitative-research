## Emergency telemetry scope

The offline counter contract accepts explicitly fictional cumulative four-component snapshots, bound to session, with ordered positive sequence numbers and nondecreasing components. Identical repeated snapshots are deduplicated, not summed. Replayed sequence conflicts, reversed counters, changed session or unverified source tags cause a measurement-integrity stop. A validated fictional lower bound at 200,000 emits `CANCEL_IF_SUPPORTED`; the recorded decision remains visible if later observations conflict. The current code always reports `cancellation_performed=false` and native CLI support UNKNOWN.

This is a tested decision interface, **not an implemented or tested live cancellation mechanism**. A fictional source tag is not proof of real telemetry provenance. There are no measurements before terminal usage unless supplied to the fictional review; absence of a live meter is not a startup failure or zero consumption. A future reviewed collector must independently establish native counter semantics, provenance, scope, reset behavior and session association before using them to cancel. If reliable live counts are unavailable, final totals can stop later dispatch only. Already-started provider work may continue after a best-effort cancellation; timeouts and two visible generations do not bound invisible work.
