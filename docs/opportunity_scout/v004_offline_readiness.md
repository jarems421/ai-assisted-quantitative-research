## Failure-preserving rehearsal

An exclusive lock protects a hash-chained, fsynced journal. Before reading a result, `start()` durably consumes the next frozen slot, binds its request/runtime hash and reserves a unique fictional sterile directory/session. `finish()` accepts one recorded invocation and no callback. A new handle cannot finish or resume a pending marker; interruption is a consumed failure requiring owner review. A run-stop result prevents every later start. An ordinary JSON/schema/lane-semantic failure consumes its slot and can advance once to the next frozen slot, without repair or replacement. This implements Path B's **proposed** distinction in fictional rehearsal; it does not approve that rule for real work.

Single use is enforced within one bound journal. Rehearsing the same fictional package in another new journal creates a separate simulation, not a second scientific dispatch. Any future live implementation must bind the one approved journal/path and durable reservation identity in consent, reject duplicate/forked runs, and pass independent crash/concurrency tests before hosting. Hash chains detect accidental/unilateral artifact changes; they are not signatures or an adversary-proof append-only filesystem. A partial write or leftover lock stops work; no repair/reset command exists.

The raw adapter requires ordered, disjoint assistant text fragments and exact terminal equality to their concatenation. Same-message thinking/text fragments count once; a new assistant ID is another visible generation. At most two are allowed, with a unique request ID per generation, the same session/model, first stop `max_tokens`, an exact synthetic output-limit notice, and an unfinished first JSON response. A complete earlier answer cannot be replaced, even if schema-invalid. Missing/changing/unexplained IDs, unknown notices/events, tools/formatter calls, changed context/model, a third generation, reordered/repeated snapshots and inconsistent assembly stop the run. No trimming, fence extraction, repair, candidate selection or rollback occurs. Schema/lane checks call the existing complete schema and citation/causal-chain validators; failures preserve their original bytes without private error messages in summaries.

**The notice and fragment profile is fictional, not a certified Claude CLI wire contract.** Older hosted probes did not validate this new configuration. A real output-limit recovery that rewrites the answer, or a CLI that reports only the final continuation instead of exact assembled text, would fail. Thinking fragments are retained in the original stream, but excluded from JSON text assembly; reported thinking tokens remain part of output totals. Unknown underlying provider requests/context remain UNKNOWN even when every visible check passes. No hidden-request prevention or independent provider-usage certificate is claimed.

Original stdout/stderr bytes, assembled UTF-8 output, supplied monitoring, recording metadata and receipt are written once under a private attempt directory. Journal loading verifies hashes and independently replays every receipt from the originals. Parsed invalid/surplus content remains in the private receipt; all 12 intended attempt slots and 24 intended card slots remain in status. No attempt is silently replaced or dropped. The offline status can say all fictional workflow slots finished; `complete_scientific_comparison` remains false, with independent reviews and human effort UNKNOWN.
